GAPS LEDGER

Four parts: gaps in this return; commission rules that bent when I built against them; tightenings I had to
invent; exhibit statements I tested. Part 4 is a table of measurements, one line each.

======================================================================
PART 1. GAPS IN THIS RETURN  (open)
======================================================================
G1  Names. The core has no rule from a name to a prime, so "every mechanism stated as addressing, write
    and read rules" is only true from the prime inward. Two policies are provided and both cost something:
    dictionary (knowledge.zig; exact, but the dictionary is an index) and hash-to-prime with probing
    (named.zig; no dictionary, but a collision makes the bytes order-dependent, a false "found" measured
    0.11% in a crowded range, and removal can only be a tombstone).
G2  Speed. Every operation is O(size of the store). Reads are 170x (250 facts) to 600x (1,000 facts) slower
    than the exhibits' table lookup on the same machine, and the gap grows linearly. Residue pages are the
    proposed fix and are unbuilt.
G3  Persistence. Every write changes every limb of K (measured 1.0000): no append log, no incremental write.
G4  Retrieval by endpoint. "All facts about subject X" has no index and needs a candidate list.
G5  Key universe. The code uses primes below 2^32 (203,280,221 keys). Hash-to-prime collision probability is
    about n^2/(2 x 203M): 0.25% at 1,000 names, 22% at 10,000. The mathematics has no such limit; the code does.
G6  Capacity is a comptime parameter. Fail-closed (error.Overflow, base unchanged), not growable.
G7  Integrity. None by default. The seal detects corruption with probability about 1 - 2^-32 using a
    non-cryptographic digest; it does not correct and goes stale on any write.
G8  Data. Everything was measured on synthetic keys and values. No natural-language corpus. Timing at
    n <= 1,500 facts; order-independence at n <= 400; glue at <= 300 facts (it is O(size^2)).
G9  Platforms. x86_64-linux and wasm32-wasi (32-bit, little-endian) were run. Big-endian was not; the
    encoding is explicit big-endian by construction.
G10 Timing figures exist for Zig 0.14.1 and 0.15.2 only; std.time timers are gone in 0.16 and 0.17.
G11 Validity. decode cannot prove M is squarefree or has only prime factors; verify(universe) can, by scanning.
    put refuses a store whose M repeats a prime, but get and has on such a store return unspecified values.
G12 Priority. Three web searches found the Chinese Remainder Theorem in residue number systems and in the
    Mignotte and Asmuth-Bloom secret-sharing schemes, and prime-power Godel numbering. None found a CRT
    key-value store or a gcd-of-differences comparison of two bases. Absence of evidence; no priority claim.
G13 Glue reports Conflict without saying which keys; use diff for that.

======================================================================
PART 2. COMMISSION RULES THAT BENT  (what failed when I built against them)
======================================================================
B1  "Single command; Zig only". ziglang.org was unreachable from the sandbox (HTTP 403 on CONNECT). The
    toolchains are the PyPI `ziglang` wheels for 0.14.1, 0.15.2, 0.16.0 and 0.17.0; pip was used only to fetch
    them. `zig build` is not provided: build.zig APIs differ across those releases. `zig test src/root.zig` is
    the command.
B2  "No Python anywhere in the deliverable". Satisfied. Outside it: Python's stdlib zipfile listed the archive;
    Python's int was an independent oracle for the bignum (460 vectors, operands up to 12,160 bits; scratch,
    not shipped); rustc compiled the exhibit modules for the measurements marked [R]; Node ran the wasm builds.
B3  "Scale claims must name the corpus size". All data is synthetic (G8).
B4  TEST 4's spent list names phase accumulation, FFT bins and moire mask differencing as structures "the
    exhibits" use. The package has no code for them (no FFT, phase store, grating mask, bitset popcount,
    bytes-as-floats or byte cube); they appear only in SEED_FORMATS.txt. I treated them as spent anyway.
B5  Zig 0.17.0 rejects `[_]T{x} ** N`; replaced by @splat. Zig 0.16 and 0.17 removed std.time timers.
B6  A defect in my own code was found by review, not by the tests on x86_64: decode computed `at + ml + 4`
    from an attacker-controlled length, which wraps a 32-bit usize. A mutation run on wasm32 confirmed the panic
    ("integer overflow"); x86_64 hides it. Fixed with subtraction-based bounds and pinned by a test.

======================================================================
PART 3. TIGHTENINGS I HAD TO INVENT
======================================================================
T1  Fixed-capacity bignum with documented headroom (add/mulSmall need 1 limb, addMulSmall 2, put 3): no
    allocator, so identical bytes on every compiler.
T2  My own SplitMix64 and FNV-1a, because std.Random and std hashes change between releases.
T3  keysInto checks its answer by recomposition (product of keys found == M) and reports IncompleteUniverse.
T4  verify(universe), a strict decoder, and a refusal in put when M repeats a prime.
T5  The seal as an ordinary fact under the reserved key 4294967291.
T6  Named-layer layout: 12-bit fingerprint, 16-bit payload, payload 0xFFFF reserved as the tombstone.
T7  "Same facts" for determinism means the finite partial function key -> value, not names.
T8  Provenance by residue class mod 8, and values packed as relation(7) confidence(4) domain(4) modality(3).
